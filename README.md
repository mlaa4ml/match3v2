# Матч-3

Игра "три в ряд": обычный режим (6 цветов, 25 ходов) и своя игра (число
цветов, число ходов, форма поля — квадрат/прямоугольник/ромб/крест/кольцо/
треугольник/восьмиугольник). Чистые HTML/CSS/ES-модули, без сборки и
бэкенда — весь прогресс/статистика хранятся в localStorage браузера.

## Локальный запуск

Открывать `index.html` двойным кликом (по `file://`) не получится —
браузеры блокируют ES-модули (`<script type="module">`) с локального диска.
Нужен любой локальный веб-сервер, например:

```
python3 -m http.server 8000
```

и затем открыть `http://localhost:8000` в браузере.

## Деплой на GitHub Pages (автоматический)

В репозитории уже есть workflow `.github/workflows/deploy-pages.yml`: при
каждом пуше в ветку `main` он прогоняет тесты и, если они прошли,
публикует игру на GitHub Pages.

Один раз перед первым пушем нужно вручную включить сам механизм в
настройках репозитория (GitHub этот шаг не разрешает делать через
workflow):

1. Settings → Pages → Build and deployment → Source → выбрать
   **"GitHub Actions"** (по умолчанию там "Deploy from a branch" — с этим
   вариантом workflow работать не будет).
2. Запушить в `main` (или запустить workflow вручную во вкладке Actions →
   "Deploy to GitHub Pages" → "Run workflow").
3. Через минуту-две адрес сайта появится в Settings → Pages, обычно вида
   `https://<username>.github.io/<repo>/`.

Дальше — само собой при каждом пуше, ничего руками поддерживать не нужно
(в отличие от временного сервера в Codespaces, который надо запускать
заново после каждой остановки контейнера).

**Если проект — не весь репозиторий, а подпапка** (например, вы положили
эти файлы в `match3/` внутри репозитория с чем-то ещё), поправьте `path:`
в шаге "Upload artifact" в workflow-файле на эту подпапку.

## PWA (установка на телефон)

В проекте есть `manifest.json` и `sw.js` — при открытии сайта в мобильном
браузере можно "Добавить на главный экран", после чего игра открывается
как отдельное приложение (без адресной строки) и работает офлайн после
первого запуска.
